# PicMuse 官网视觉与营销设计系统

更新时间：2026-09-15

## 1. 设计定位

### 核心判断

PicMuse 首期不是“AI 技术介绍页”，而是一个面向移动创作者的**结果展示型下载站**：

```text
看到结果
  -> 理解能解决什么问题
  -> 相信产品真实可用
  -> 下载 PicMuse
```

用户不需要先理解模型、参数或技术名词。页面应先展示真实的图片/视频变化，再解释功能和使用场景。

### 品牌气质

建议定位为：

- 有创意，但不吵闹
- 高级，但不疏离
- 真实，但不廉价
- 面向普通创作者，而不是只面向专业设计师
- 有商业转化意识，但不使用夸张承诺

关键词：

```text
Visual
Playful
Confident
Useful
Mobile-first
```

## 2. 视觉方向

### 方向名称

**Creative Proof Lab：创作结果实验室**

主视觉不是抽象 AI 光效，而是真实的作品、前后对比、短视频和手机端使用场景。页面像一个精心策划的创作展览，但每个展示单元都服务于理解和下载。

### 色彩系统

在拿到 PicMuse 官方品牌色之前，使用以下临时官网色板。后续只替换 token，不改变组件结构。

| Token | 色值 | 用途 |
|---|---|---|
| `ink` | `#171717` | 主标题、深色区、主要文字 |
| `paper` | `#FBFBFF` | 页面主背景 |
| `white` | `#FFFFFF` | 内容区和媒体底色 |
| `mint` | `#86F7E3` | Logo 渐变起点、轻量标签 |
| `violet` | `#8A71FF` | Logo 渐变中段、品牌强调 |
| `purple` | `#B45BFF` | 链接 hover、功能分类 |
| `pink` | `#F258D3` | Logo 渐变终点、主 CTA 渐变 |
| `muted` | `#6D6D68` | 次级文字 |
| `line` | `#DEDDD7` | 分割线、边界 |
| `warning` | `#B54708` | 18+ 和风险提示 |

使用规则：

- 页面主背景以 `paper`、`white` 和 `ink` 交替，避免整站只有一种色调。
- 主 CTA 使用青绿到蓝紫再到粉紫的品牌渐变，贴近当前 PicMuse App 图标。
- 紫色只作为品牌渐变的一部分，不把整站做成单一紫色主题。
- 不使用发光球、模糊光斑和装饰性气泡。
- 18+ 提示使用清晰的 `warning` 色，不使用暧昧的粉色营销视觉。

### 字体

最终字体以品牌资产为准。临时基线：

- 英文：`Manrope` 或 `DM Sans`
- 韩语、日语、繁体中文：使用系统无衬线 fallback
- 正文：高可读性无衬线
- 数字、版本和参数：使用等宽或半等宽风格

字体规则：

- H1 是有气质的短句，不写成大段营销口号。
- 正文行宽控制在 60-75 个字符。
- 不使用过度紧缩字距。
- 不用 viewport 缩放字号。
- 多语言标题允许自然换行，不强行保持一行。

### 圆角、阴影和边框

- 普通内容区域不做浮动卡片化。
- 重复内容单元可以使用最多 `8px` 圆角。
- 主要媒体使用自然比例，不加厚重装饰框。
- 阴影只用于下载浮层、视频控件和需要层级的交互。
- 分区通过留白、背景色和分割线区分，不把每个区块包成卡片。

## 3. 组件基线

### 主要 CTA

主要 CTA 统一为：

```text
Download PicMuse for Android
```

规则：

- 首页首屏只有一个主 CTA。
- 功能页首屏和页面末尾可以重复同一个 CTA，但文案保持一致。
- CTA 必须带 Android/Google Play 语义，不使用含糊的“Try now”。
- 按钮旁边可显示 `18+` 或“Free download”类事实，但不能虚构免费额度。
- 记录 `store_click`，附带 `content_id`、`locale`、`page_type`、`cluster`。

### 次级操作

- 功能导航使用文字链接或带图标的链接。
- 语言切换使用菜单，不用一排长语言按钮。
- 视频使用原生播放控件或明确的播放按钮。
- 图像前后对比使用拖动条，但必须提供静态前后图和 alt 文本。
- 不使用无法理解含义的纯图标按钮；陌生图标提供 tooltip。

### 图像与视频

- 首屏使用真实产品截图、真实生成结果或手机场景。
- 每个视频同时提供 poster、字幕或文字稿。
- 图片必须预留宽高，避免 CLS。
- 不用模糊、过度裁切或只表达氛围的素材代替产品证据。
- 18+ 内容默认不放在首页第一屏；在专属功能页中清楚标注。

## 4. 营销信息架构

### 信息优先级

每个页面按以下顺序传递：

```text
结果
  -> 场景
  -> 方法
  -> 证据
  -> 限制
  -> 下载
```

### 文案公式

功能页首屏建议使用：

```text
[用户想完成的事情]
[PicMuse 能提供的结果]
[真实示例或视频]
[Download PicMuse for Android]
```

避免：

- “下一代革命性 AI 平台”
- “无限、完美、零门槛”等未经确认的承诺
- 只讲模型名称，不讲用户结果
- 把 App 功能写成可以在网页直接使用

### 信任信号

官网首期可使用：

- 官方 Google Play 下载链接
- 应用名称和包名对应关系
- 真实商店截图
- 产品更新时间
- 功能边界和适用平台
- Privacy、Terms、User Agreement
- PicMuse 与 PicSelf 的平台关系说明

不应直接使用：

- 未授权用户作品
- 不能核实的评分和下载量
- 竞品评价或截图
- 没有版本依据的价格、积分和模型承诺

## 5. 18+ 视觉与营销规则

- AI 写真、丰胸、身体编辑页面显著显示 `18+`。
- 首页不使用具有明显性暗示的首屏视觉。
- 不使用未成年人、校园、制服、幼态、年龄模糊的人物素材。
- 不用“变得更性感”“吸引未成年人”等诱导式表达。
- 说明功能是图像创作/编辑能力，不把身体变化写成健康或医学效果。
- 搜索标题和摘要使用中性、产品化描述。
- 18+ 入口不能绕过年龄提示，也不能暗藏在普通模板页中。

## 6. 多语言设计规则

支持路径：

```text
/en/
/zh-tw/
/ko/
/ja/
/de/
/es/
```

- 语言切换使用普通链接，始终能被搜索引擎抓取。
- 繁体中文使用一套内容，不拆分台湾和香港。
- 语言不是逐字翻译：标题、CTA、场景和示例要符合当地表达。
- CTA 组件设置稳定最小高度，避免不同语言改变页面布局。
- 德语长词、日语标点、韩语字宽和繁中换行都要做真实设备检查。
- 未完成翻译的页面不进入 sitemap。

## 7. 响应式基线

### 移动端

- 先设计 320px-430px 宽度，再扩展桌面。
- 首屏优先顺序：品牌、结果图/视频、价值说明、下载 CTA。
- 导航收敛为 Logo、菜单、下载按钮。
- 视频默认点击播放，避免消耗流量。
- CTA 使用固定可点击高度，触控区域至少 `44px`。
- 不使用横向滚动展示核心信息。

### 桌面端

- 最大内容宽度建议 `1200px` 左右。
- 视觉媒体可以占更大面积，但文字列宽保持可读。
- 首页允许左右分栏，但首屏不能变成“文字卡片 + 图片卡片”的机械模板。
- 重要内容保持在首屏下方可见，给用户明确的继续浏览信号。

## 8. 设计验收

- 320px、375px、390px、768px 和桌面宽度无横向溢出。
- 首页首屏 5 秒内能说清“PicMuse 是什么、能做什么、如何下载”。
- 每个功能页首屏能看到真实产品证据。
- 主要 CTA 不被视频、语言菜单或长标题挤压。
- 18+ 页面有明确提示，且视觉和文案不越界。
- 颜色扫描后不呈现单一紫色、深蓝或米色主题。
- 页面没有装饰性渐变球、模糊光斑或重复嵌套卡片。
